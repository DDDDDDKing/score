# 中南大学第十二届大学生职业规划大赛 · 大众评委云端评分系统

面向 **2026 年 11 月 8 日初赛**，两个入口共用一套 Supabase 数据库。与现有 GitHub 仓库中其他文件无关。

## 入口与功能

- 评委端 `index.html`：本科生/研究生评委凭管理员预先导入的姓名、学号 **一次领取激活凭证**；支持成长赛道与就业赛道逐位选手的分项评分、提交后锁定、本人历史评分及进度查询。每人每位选手最多提交一条评分。
- 管理端 `admin.html`：独立邮箱密码登录及管理员白名单；手工添加/Excel 导入两类大众评委、手工添加/Excel 导入参赛选手；修改可见性、停用评委、重置激活；现场打分监控、分项成绩汇总、查看每人每位选手的评分明细、撤销误提交、导出 CSV；录入专业评分；修改权重和开放/暂停评分。
- 成长赛道：职业目标 20、行动成果 40、目标契合度 30、实习意向 10。
- 就业赛道：通用素质 35/45、岗位认知 20/15、岗位胜任能力 25/20、发展潜力 10、录用意向 10（随就业类别改变）。
- 总成绩：`专业评分 × 70% + 研究生平均分 × 20% + 本科生平均分 × 10%`。两组评委人数可任意增减，80/20 不是数据库硬限制。某组暂无评分或未录入专业分时显示 `—`，不使用 0 分误算。

## 正式上线前必须做（Supabase 目前尚未连接到此项目）

1. 登录 [Supabase](https://supabase.com/dashboard)，在你指定的组织新建 **独立项目**，推荐选择离中国大陆观众较近的区域。注意不要复用其他生产项目的人员权限表或凭证。
2. 在 SQL Editor 中粘贴并执行 [`supabase/schema.sql`](supabase/schema.sql)，检查创建成功、RLS 开启，所有新建表的 `anon` 访问权限均被撤销。
3. 在 Supabase → Authentication → Users 中手动添加/邀请管理账号（使用邮箱和密码）；确认邮箱可正常登录。
4. 再在 SQL Editor 执行下面语句，把邮箱替换成刚才创建的管理员邮箱：

   ```sql
   insert into public.cv_admins (user_id)
   select id from auth.users where email = 'admin@example.com'
   on conflict do nothing;
   ```

   如返回0行，核实邮箱已被创建且认证成功；严禁设置 `cv_admins` 的匿名 INSERT 策略。
5. Supabase Project Settings → API / Connect 中复制 **Project URL** 与 **publishable key**（或旧版 `anon` key），填写到根目录 [`config.js`](config.js)。**绝不能把 service_role、secret key、数据库密码写入前端文件**。
6. 在 GitHub Pages 启用站点。若本项目放在 `DDDDDDKing/score` 仓库的 `career-vote/` 目录，则页面地址（启用后）将是：
   - 评委端：`https://ddddddking.github.io/score/career-vote/`
   - 管理端：`https://ddddddking.github.io/score/career-vote/admin.html`
   - 在 GitHub 仓库 Settings → Pages 中启用 Deploy from a branch → `main` → `/ (root)` → Save。启用生效前，上述网址不可用于正式活动。
7. 在管理端先导入名单，设置赛事名称并添加选手；**完成后再开启评分**。建议至少用两个测试账号分别模拟本科生、研究生评分，并核对专业分/合成分。

## Excel 名单模板

下载文件：`评委及选手导入模板.xlsx`。包含 4 个工作表：

| 工作表 | 必填字段 | 管理端导入方法 |
|---|---|---|
| 本科生评委 | 姓名、学号 | 选择本科生评委再上传该文件 |
| 研究生评委 | 姓名、学号 | 选择研究生评委再上传该文件 |
| 参赛选手 | 姓名、赛道、就业类别（就业赛道必填）、展示顺序 | 参赛选手 → 批量导入 |
| 填写说明 | 规则与演示（不参与导入） | 仅供阅读 |

**务必把学号保存为 Excel 文本格式**，防止前导0丢失和大数字被转换为科学计数法。后台导入会跳过已存在且姓名/组别一致的学号；若同一学号对应不同姓名或组别，则直接提示冲突，不会覆盖已激活凭证。

## 权限、防重和实际安全边界

- `cv_judges` 存储学号，**评委端不能批量读取评委名单**；实名+学号匹配通过数据库 RPC 完成。
- 激活由 SQL 单条原子 UPDATE 实现，已激活的同一学号无法再次领取新凭证。激活令牌仅保存在初次激活的浏览器 localStorage，其 SHA-256 摘要存于云端；设备丢失需要管理员执行重置激活。
- 提交由 SQL 唯一索引 `(judge_id, contestant_id)` 和 RPC 实现，不允许重复投同一选手；分项分数范围由数据库再次校验（步长0.5）。
- 网站采取 RLS + 仅向管理员开放数据表读写 + 最小权限的公开 RPC。管理端必须使用真实 Supabase Auth 管理账号，不在网页写死管理员密码。
- **姓名+学号不是强认证**：若他人提前掌握这两项，可冒名抢先激活。激活令牌被复制后也可以在另一浏览器使用，因此这里实现的是**一次激活，不是硬件级只能一台手机登录**。若比赛需要防冒名，建议给每位评委另发随机一次性 PIN 或增加现场扫码签到、身份人工核验。
- 现场开赛前务必人工确认「实习意向」和「录用意向」条目的给分方式；策划书将其列为评分项，但这些项目涉及用人单位意向，通常由组织方统一核定，不宜让大众评委凭主观印象自由评分。当前版本严格保留策划书的四项/五项评分框架，尚未设置单独的组织方奖励分录入接口。
- 默认没有防刷验证码/边缘速率限制；正式开放应补充 Supabase Edge Function 限流/验证码或使用强一次性 PIN，防止枚举学号、恶意占用评委身份。
- 系统不自动证明扫码者就是学号本人，活动中应配套现场身份核对。

## 本地测试

本项目是纯 HTML、CSS 和原生 JavaScript 的静态前端，依赖外部 CDN 加载 `@supabase/supabase-js@2.49.8` 与 `xlsx@0.18.5`。无需 npm install。

```sh
python -m http.server 8080
```

打开 `http://localhost:8080/` 和 `/admin.html`。完成 SQL、管理员初始化与 config.js 后可进行端到端测试。使用 GitHub Pages HTTPS 对应的静态文件即可线上访问。

## 事件与数据备份

正式活动前用少量**非真实姓名与学号**做功能测试，结束后把测试账号和选手删除，再导入真实名单。云端日志可能保留登录和投票痕迹，依据组织方的隐私政策处理学号。比赛结束后关闭评分并导出两份 CSV（汇总与明细），留存线下备份。
